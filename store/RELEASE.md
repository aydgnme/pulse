# Pulse — App Store release checklist

Everything in the repo is ready; the steps below are the ones only you can do
(they need your Apple account).

## One-time setup

1. **Apple Developer Program** membership ($99/yr) — [developer.apple.com](https://developer.apple.com/programs/enroll/)
2. **EAS CLI:**
   ```bash
   npm install -g eas-cli
   eas login          # Expo account (free)
   ```
3. Link the project (writes `extra.eas.projectId` into app.json — commit it):
   ```bash
   cd pulse
   eas init
   ```

## Build & submit

```bash
eas build --platform ios --profile production
```
- First run asks for your Apple ID and handles certificates/profiles
  automatically. The bundle id is already set: `com.aydgnme.pulse`.

```bash
eas submit --platform ios
```
- Uploads the finished build to App Store Connect (can also be done with the
  Transporter app).

## App Store Connect — 1.2.0 update

1. My Apps → **Pulse: One Tap Timing** → **＋** next to iOS App → version
   **1.2.0**.
2. Paste "What's New in This Version" from the 1.2.0 entry in
   [`../CHANGELOG.md`](../CHANGELOG.md) (EN + TR locales).
3. **App Privacy** remains "Data Not Collected" — the shared link carries only
   an integer score, with no backend, no analytics, and no account.
4. **Universal Link requirement:** 1.2.0 introduces a Universal Link feature
   via shared run images. The domain `pulse.aydgn.me` must be live and serving
   `/.well-known/apple-app-site-association` over HTTPS with no redirect before
   the build is submitted, or the universal link silently fails to open. The
   files are ready in the `web/` directory; publish them before submission.

   **Deploy mechanism is still undefined.** `web/.nojekyll` is in place so
   GitHub Pages won't run its default Jekyll build and strip the dot-directory
   containing the AASA file — but GitHub Pages only serves from the repo root
   (`/`) or `/docs` on a branch, or from a `gh-pages` branch. It does not serve
   an arbitrary `web/` directory as-is. The maintainer must pick one of these
   (e.g. publish `web/`'s contents to a `gh-pages` branch, or via a
   `/docs`-on-`main` copy/symlink) and point the `pulse.aydgn.me` DNS/CNAME at
   it before submission.
6. Select the build uploaded by `eas submit`, then **Submit for Review**.

## Regenerating the App Preview

`preview/pulse-app-preview-6.5.mp4` is 886x1920 / 25s / 30fps / H.264 High 4.0
with AAC stereo — the size App Store Connect accepts for every current iPhone
class from 6.1" to 6.9". Up to three previews per localisation are allowed.

Unlike the screenshots, this is not regenerated by a script: it is a recording
of a real run, so reproducing it means recording again. The steps:

1. **Add the capture hook to `src/Game.tsx`.** The game needs to play itself —
   nobody can hit a 13-degree window by hand while also driving the recorder.
   Add a module-level `const DEMO_AUTOPLAY = true`, a `demoLastTap` ref and an
   `onTapRef` ref kept pointing at the live `onTap`, then inside the rAF loop,
   after `prevDist.current = d`, fire `onTapRef.current()` whenever `d` falls
   inside `window.current * TUNING.perfectFraction * 0.45` (with a ~120ms
   cooldown). Add an effect that calls `onTapRef.current()` 2.2s after the menu
   appears, so the capture opens on the wordmark before play starts.

   Everything recorded is then the real game — real loop, real difficulty ramp,
   real rendering. Only the thumb is synthetic. **This hook must never be
   committed.**

2. **Serve the JS and launch.** The Release configuration currently fails in
   CocoaPods' `[RNDeps] Replace React Native Dependencies` script phase, so use
   the Debug app against Metro, which picks the hook up without a rebuild:

   ```bash
   npx expo start
   xcrun simctl boot "iPhone 17 Pro"
   xcrun simctl install booted ios/build/*/Build/Products/Debug-iphonesimulator/Pulse.app
   ```

3. **Clean the status bar** (this works on iOS; it is unsupported on watchOS):

   ```bash
   xcrun simctl status_bar booted override --time "09:41" \
     --dataNetwork wifi --wifiMode active --wifiBars 3 \
     --batteryState charged --batteryLevel 100
   ```

4. **Record, starting the app after the recorder** so the launch is captured,
   then trim the home screen off in the next step:

   ```bash
   xcrun simctl io booted recordVideo --codec h264 --force raw.mov &
   sleep 2 && xcrun simctl launch booted com.aydgnme.pulse
   sleep 32 && kill -INT %1
   ```

5. **Encode to spec.** Check where the app actually appears first
   (`ffmpeg -ss <t> -i raw.mov -frames:v 1 f.png`) and start the trim there —
   the first seconds are the home screen and must not ship. The scale-then-crop
   avoids the 0.3% distortion a straight resize to 886x1920 would introduce,
   and the audio is the game's own loop, synthesized by `make_music.py`:

   ```bash
   ffmpeg -ss 5.5 -t 25 -i raw.mov -stream_loop -1 -i assets/audio/theme.wav \
     -filter_complex "[0:v]scale=886:-2,crop=886:1920,fps=30,setsar=1[v];\
       [1:a]afade=t=in:st=0:d=1,afade=t=out:st=23.5:d=1.5,volume=0.5[a]" \
     -map "[v]" -map "[a]" \
     -c:v libx264 -profile:v high -level 4.0 -pix_fmt yuv420p \
     -b:v 11M -maxrate 12M -bufsize 24M \
     -c:a aac -b:a 256k -ar 48000 -ac 2 -shortest -movflags +faststart \
     store/preview/pulse-app-preview-6.5.mp4
   ```

   The average bitrate lands well under Apple's 10-12 Mbps guidance because the
   frame is mostly flat dark ground. That is the encoder hitting its quality
   target cheaply, not a quality loss — do not pad it.

6. **Revert the hook and clear the status bar.** Confirm with
   `git diff --quiet src/` and `xcrun simctl status_bar booted clear`.

## Sanity checks before submitting

```bash
npx expo-doctor          # config/dependency health
npx expo start           # play a run on a real device via Expo Go
```

Review typically takes 24–48 h. Common first-app rejections to avoid are
already handled: the app works offline, has no login, no placeholder content,
and no broken links.
